## 下次相似需求沿用的流程

1. 在右下角立绘上方点“切换形象”，可选择黑白熊（默认）或莫奈美；切换本身不提交任何生成请求。输入主题或教学要求，支持中文，例如“用中文讲解重力，先用小球落地做演示，再解释为什么月球不会掉下来”。支持“重力”这样的两个字短主题；输入法确认选字不会触发提交。开始后固定本轮角色，两次续讲继承同一形象；新课程可重新选择。
   若问题和角色与已有记录一致，先显示4.5秒的课堂加载，再直接使用已保存的脚本与本地视频，跳过下面的规划和生成步骤；已有路径中的续讲按同样方式加载。已命中但文件不完整时明确报错，不退回付费生成。
2. Gemini `gemini-3.1-flash-lite` 只规划当前选中的一段课程，一次产出整段 JSON 脚本。开场 30 秒，6 个连续的 5 秒镜头；中文需求默认简体中文标题、普通话台词、中文字幕和三个中文续讲问题。明确指定其他讲解语言时遵从该要求。视觉动作描述和 JSON 字段保持英文。
3. 本地编译每个镜头所选角色的编号角色表、画面动作、原文台词、声音描述和风格提示。视频沿用原仓库的70年代美式教学动画：平涂、墨线轻微抖动、复古暖色背景、纸张与16mm胶片颗粒；角色保留黑白熊的黑白配色或莫奈美的粉白配色。提交到唯一允许的 `minimax/h3-max-turbo/image-to-video`。每段 5 秒、768P、seed 314159、balanced prompt expansion。目前不传首图，使用该端点可省略 `image_url` 的方式；不会改用其他 fal 端点。
4. 最多同时生成两个镜头；播放器预加载并解码，用原仓库的连续播放与统一背景音乐衔接。镜头是独立生成的，没有传递上一段尾帧；相邻动作或声音的完全一致尚需真实成片验证。
5. 看完或观看中由用户手动选续讲。最多两次，每次 10 秒、两个镜头。只展示建议不生成其他分支；不自动倒计时跳转。全路径为 30 + 10 + 10 = 50 秒，最多 10 个视频提交。
6. 付费提交不自动重试。出现失败后不发起新的镜头或尚未开始的后续课程；已经受理的并发请求允许完成。请求超时不代表未扣费，先查已有 fal request ID，不能为补记录重新提交。

成本配置快照：按当前代码中的每秒 0.01 美元估算，完整路径 fal 约 0.50 美元；Gemini 单独计费。用户告知 fal 余额 0.98 美元，不代表已实时查询账户余额。促销有效性由代码保守限制在 2026-09-07 00:00 UTC 之前；到期后先核实价格，不自动沿用历史估算。任何日志中的 `actualBilledCost: null` 都表示尚未取得实际账单。

## 实际生成记录的位置与读法

默认开启 `SAVE_RECORDINGS=1`。首次提交后生成 `recordings/<sessionId>/`，不需要再次让 agent 记录。

| 文件 / 事件 | 保存的事实 |
| --- | --- |
| 主课程的 `events.jsonl` / `lesson-selection` | 原始主题、所选 `teacherId`、选择顺序、30/10 秒时长、命令 ID、子课程 ID 和上段课程 ID |
| 子课程的 `events.jsonl` / `playlist-link` | 子课程属于哪个主课程、承接哪一段 |
| `lesson-request`、`planner-request` | 开始规划的主题、配置、模型、完整请求体；写入发生在 API 提交之前 |
| `planner-response`、`lesson-prepared` | Gemini 的公开文本输出、可用 token 用量、解析后的镜头脚本；不保存思考文本 |
| `planning-failed` | 脚本请求或解析失败；不会继续提交视频 |
| `video-request` | 镜头脚本与发给 H3 的完整输入；这只是提交意图，不能单独证明服务端已受理 |
| `video-submitted` | fal 已返回的 request ID，可用于之后核对同一任务 |
| `video-completed`、`video-failed` | 实际结果 URL、改写提示、服务日志与耗时，或错误和已知 request ID；实际扣费保持未知 |
| `scene-NN.json` | 所选 `teacherId`、成功结果的台词、原提示、fal 改写提示、URL 和耗时；视频下载前先保存 |
| `scene-NN.mp4`、`video-saved` | 已下载完成的实际视频文件 |
| `video-save-failed` | 成片下载失败的记录；元数据仍保留，不把它当成已下载的文件 |

下次先按主课程的选择记录找到各个子课程，再读取各自的脚本、视频和事件。不把不同 session 的 `scene-01` 混成同一段。缺少完成事件时按未完成/状态未知处理；服务重启不会自动恢复内存中的课堂和远程任务。保存的提示与种子便于复用流程，不保证重新生成逐帧相同。

元数据写入失败会阻止新付费请求。若已经提交之后磁盘才出错，服务器会报告记录错误并继续接收已付费结果；这种情况下不能声称记录完整。视频下载失败不会触发重新生成。
