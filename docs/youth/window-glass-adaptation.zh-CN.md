# 窗玻璃参考与适配边界

采用 web-shader-extractor 的源码核对方法。本次用户要求直接优化现有教室、不做 A/B，因此不建立完整小镇复刻或新主题，不把适配结果宣称为原页面逐像素重放。

## SOURCE：直接核对的事实

- 来源 `Kenton-GMI/sakuragaoka-station`，固定提交 `4112f57208b7e29998344ca71fef74202c2b2bdd`，MIT 授权。
- 目标仅为 `src/core/materials.js` 的 `glass()`，不是整个 canvas 的后处理效果。
- `src/world/station/mats.js` 为外玻璃调用 `glass({tint:'#9fb6c8',opacity:0.34})`，为内玻璃调用 `glass({tint:'#c3d0d8',opacity:0.14,streaks:false})`；实际着色器的 `uOpacity + fres*0.35` 控制视角透明度。
- 着色器使用世界坐标法线、摄像机方向、三次 Fresnel、反射方向的 Y 分量推算天空颜色；不读取场景颜色纹理、不需要 refraction RTT。透明混合，关闭深度写入，双面。
- 原片元还可加入斜线条纹和磨砂项，本教室关闭这两种外观。

## 本项目设计决定（不是原项目参数的逐项复刻）

- 保留原公式、默认天空色，使用 0.14 基础透明度；不复制雾效、实例化分支或条纹。
- 玻璃是平面而不是薄盒，`forceSinglePass` 避免不必要的双面双绘制。
- 现有场景没有后处理颜色输出步骤，故添加 Three `colorspace_fragment`，由线性工作色转换至 sRGB；不使用曝光参数补偿缺失管线。
- 原墙面没有窗洞，仅换材质无法通透。因此窗墙、门墙结构一并修改；天空是静态两三角面配色背景，不是完整外景。
- 窗框金属仍是既有 Phong；全室照明和接触暗部重新离线烘焙，绝不因玻璃恢复实时阴影。

## 验证与已知限制

- 单测核对单次透明绘制、无纹理采样 / 时间均匀量，以及射线可穿过真实墙洞到达玻璃。
- 后台浏览器实际拖动两个边界视角，检查画面、WebGL 错误、离屏绘制次数和静止帧数；证据在 `output/youth-bake`。
- 这是解析反光而非真实环境反射，没有镜像显示室内物体；外侧天空也没有远景建筑。它节省资源，但不能声称物理玻璃或完整小镇渲染重放。
- 没有执行原小镇与教室的像素 A/B、没有纯 GPU timer 或整机温度测量。用绘制批次与帧活动度描述成本，不把局部耗时冒充功率结果。
