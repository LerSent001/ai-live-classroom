# 独立中文课堂

> 主线调整：中文课堂现为 `/` 默认首页，`/zh-youth` 保持兼容；本地黑白熊 Demo 移到 `/styles/monokuma`。GitHub 原 `main` 可从历史提交 `2cd7d47ad0e7d8f4fd13970df5dac03068b4ed23` 取回。以下早期实施记录中的“原 `/` Demo”指调整前的路径。

## 入口与隔离

- `/`：保留现有黑白熊 / 莫奈美 Demo。原场景、运镜、角色、全局样式和入口文件未改动。
- `/zh-youth`：新中文课堂。新增组件在 `src/components/youth/`，样式全部限制在 `.youth-*` 下。
- 会话使用独立的 `zh-youth-classroom-session-v1`，不读取或覆盖 Demo 的 sessionStorage。
- 新课程复用已有的播放队列和录制实现；2026-09-22 已迁到独立 `/api/youth/*` API、浏览器钱包与按身份隔离的录制目录，规划和视频都走 TokenDance。新课程统一使用 `youth-question`，不再分年龄；旧年龄档案仅保留录像读取兼容，不用于新课，也不混用旧年龄录像缓存。钱包细节见 `tokenpay-integration.zh-CN.md`。

## 视觉与交互

布局基准为本目录 `selected-reference.png`；最终风格按用户后续要求改为低面数校园动漫背景，而非仿写实高模。奶油墙、浅木、青绿护墙、蓝色不透明玻璃；六套学生桌椅，独立讲台。无黑白熊、海报、主题名和窗外景物。黑板为数学/物理公式。

桌椅已换成 Poly Haven / Ethan Place 的 CC0 实体模型，经后台减面和顶点配色适配，每套 4,703 三角面、两份文件共 176,776 bytes。原资源、授权和可复现转换流程见 `public/youth/SOURCE.md`。门窗、电视支臂为自制静态低模，不宣称整套场景都是下载模型。窗框有厚度、把手和后退的玻璃，木门有凹凸面板，支臂用矩形外壳与独立转轴。

2026-09-22 按用户纠正，删除四阶 Toon 硬分档与几何描边，改为连续明暗、静态墙角层次、细灰泥和浅木纹。玻璃去掉插画式平面反光条，使用不透明连续色阶和局部高光。不是把人物卡通材质直接套到教室。GitHub 来源评估、旧版墙面成本与对照方法见 `anime-rendering-research.zh-CN.md`。

悬挂机械臂与电视是真实的轻量 3D 几何；机械臂固定不做物理、骨骼、IK 或持续动画。屏幕继续使用原 `LessonDeck`，待机是原来的黑屏，不加壁纸。首次播放等待镜头到位和媒体解码就绪。可在播放中查看教室，再回到屏幕。

不设幼儿园 / 小学 / 初中 / 高中分类，不推断用户年龄或预设难度上限。讲解深度、术语和例子只根据问题内容与用户明确要求决定，没有默认“小学”规则。新版本使用普通话画外讲解和教学示意内容，没有屏幕内的黑白熊或其他吉祥物。中文输入法确认回车不会提交；追问必须手动选择。

## 性能策略

- R3F `frameloop="demand"`：仅入场、镜头移动、拖看、尺寸变化和必要状态变化时更新。停稳与正常 DOM 视频播放不维持 WebGL 动画循环。
- 固定场景按材质合批，六套桌椅共用一个绘制批次；整个场景含接触阴影平面 40,072 三角面、27 次常规绘制，低于上一稿 40,528 / 29。仅载入两份家具 GLB，没有角色、骨骼、舞蹈、背景音乐加载。
- 主阴影保留 2048 分辨率以保留轮廓细节，但初始化后缓存，`shadowMap.autoUpdate=false`。地面接触阴影 512 分辨率，只计算一次。
- 删除 N8AO、环境贴图生成、后处理合成器、VSM 模糊通道；使用直接渲染、连续 Lambert 材质、仅玻璃 / 窗框的轻量 Phong 高光与缓存 PCF 阴影。没有实时地面镜面反射、Bloom、透明折射或室外景物。
- 细纹理是颜色信息，不增加独立凹凸、法线或粗糙度采样。公式 / 墙纹 / 木纹合成一张 1536 × 768、80,316 bytes 的图集，替换原 2048 × 732、90,790 bytes 的黑板贴图。图集基础像素更少，但表面采样并非零成本；以同机有限对照及预算检查为准，不声称零耗电。
- 地面接触阴影整个子树记忆化，避免 React 的 UI/媒体状态变化重置 `frames=1` 内部计数，导致反复捕获。柔和阴影通过光照配比、固定阴影强度实现，不靠逐帧重算。
- DPR 上限 1.25；保留 `preserveDrawingBuffer`，避免原项目曾出现的 DOM 视频合成黑帧。
- 修正相同版本的轮询快照重复 setState，避免静态教室每 600ms 被无意义唤醒。原 Demo 的状态语义不变。
- 新播放器只预加载当前/下一段，最多两个视频槽准备媒体；无持续电视雪花和 CRT 动画。

## 后台验证与费用边界

构建和后台浏览器以 `nice -n 15` 运行。未连接用户现有浏览器、未打开桌面窗口、未停止其他项目服务。早期视觉轮次用单 worker 的 webpack 构建；本轮钱包集成用默认 Turbopack 生产构建。

运行本地预览：`npm run build`，然后 `npm run start -- --hostname 127.0.0.1 --port 3029`。新课堂由用户连接自己的 TokenDance 钱包；原 Demo 仍用既有服务端密钥。不要通过测试提交真实生成。

交付预览显式覆盖为空 `FAL_KEY`、`GEMINI_API_KEY`，设置 `SAVE_RECORDINGS=0`，没有读取展示或修改 `.env.local` 内容。未连接钱包时生成按钮打开钱包面板、不提交课程。用户若主动连接真实 TokenDance 钱包并开始课程，则仍可能计费，不能因为这两个旧 Key 为空就当作绝对无支出模式。

验证命令：

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run verify
YOUTH_TEST_URL=http://127.0.0.1:3029 PLAYWRIGHT_MODULE=/path/to/playwright node scripts/verify-youth-browser.cjs
```

浏览器验证脚本使用隔离的无头 Chromium。真实服务只创建免费空会话；播放、切换和追问由浏览器请求拦截 fixture 模拟，视频是本地编码的小型 WebM，并非 AI 生成课程。所有外部请求被拦截，实际开始/追问命令不会发给服务端。证据位于 `output/youth-qa/`。

真实 TokenDance 授权/生成/扣费未验证；原 Demo 的 Gemini/H3 生成也未重新付费验证。原 Demo 的优惠截止保护仍保留（2026-09-07 起过期）。新课堂按用户钱包调用不同的 TokenDance 协议，不沿用旧 fal 估价；真实使用需自行确认平台额度和费用。

后台测试证明的是渲染帧、交互和本地视频衔接，不是实际课程生成，也不是机身温度或续航的量化测量。

工程与视觉证据见项目根目录 `design-qa.md`，最终验证记录以该文件和 `output/youth-qa/browser-check.json` 为准。单元测试覆盖 CC0 资产体积、面数、顶点色、无骨骼/动画/外部贴图，以及新增图集预算、连续不透明材质。测试视频不是 AI 生成课程；没有长时温度 / 续航测试。
